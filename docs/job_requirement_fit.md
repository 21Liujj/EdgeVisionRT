**这块 Orin Nano Super 8GB + UVC 头能支撑两个岗位的"硬核部分"，但两个岗位真正的标题都是 AI Agent / 端侧大模型，拼的是"嵌入式 + Agent"两条腿。**

## 5. 补齐计划（按优先级，只列为拿下这两个岗位必须的 3 件事）

1. **M1 出帧 + M2 YOLO 跑起来（最高优）**：没有实时流，后面全是空谈。这是两个岗位都会点的演示。
2. **把一个 Agent 切口做小做实（M7 的最小版）**：不搭大而全的 LangChain 系统，只做一件事——`edgevisionctl` 暴露 MCP 工具（抓帧/查状态/起停录制），一个 LangChain/LlamaIndex 的 demo 从需求定义走到落地，录屏 3 分钟。这就把安克第 2/3/5 条和字节第 5 条一次性点亮。
3. **8h 长稳 + bench 对照（M6+M4）**：字节第 1/2 条和安克"真正提效"的证据都落在这里：帧率/掉帧/温度/p50-p99/nvpmodel 档位对照，一张表讲清。

不做的（明确放弃，面试主动说）：RTOS 实机、手机 SoC 实机移植、INT8 全量、大而全的 Agent 平台。

## 6. 面试必问 3 题的话术要点

1. "Jetson 和手机 SoC/RTOS 有什么区别？你没做过 RTOS/手机，怎么证明你行？"
   答：调用路径同构（应用→内核→驱动→硬件），我在 Jetson 上做的是 Linux + 软实时（有界队列/drop 计数/长稳），RTOS 的硬实时保证我知道边界在哪，不混为一谈；手机 SoC 的 NPU/GPU 共享内存与 Jetson 的统一内存分析方法是同一套（M3 文档）。
2. "你的 Agent 作品是什么？LangChain/LlamaIndex 用到什么程度？"
   答：不吹大模型，是小而完整的工具：MCP 暴露 3 个工具，LangChain 编排"查状态→抓帧→问 VLM→落盘报告"，需求/开发/落地全周期一人走完，有录屏和复现命令。
3. "19.9 元的头能说明什么？"
   答：恰恰说明工程能力：USB2 带宽下 YUYV 必然掉帧，我用 `probe_camera.py` 的 `fits_usb2` 算出来选 MJPEG，有数据冻结选档，不是撞运气。
